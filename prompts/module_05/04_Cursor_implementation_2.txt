# Goal of this step

Implement the runtime core for Phase 5A:

- load MobileNetV2 ONNX model from assets

- create and reuse ONNX Runtime session
- run inference on already-preprocessed input (`float[]`, NCHW)

# Hard constraints

## Tensor/layout constraints
Input contract is exactly:

- `float[]`
- length `150528`
- shape `[1, 3, 224, 224]`
- layout `NCHW`

Hard rules:
- do **not** transpose
- do **not** repack
- do **not** reinterpret as HWC or NHWC
- do **not** normalize again
- do **not** call bitmap APIs from `OnnxClassifier`
- do **not** inspect pixels inside inference code
- do **not** allocate a transformed copy of input data

The classifier must treat the incoming `float[]` as already-final model input.

## Session/environment constraints
- obtain environment only via `OrtEnvironment.getEnvironment()`
- create `OrtSession` once
- reuse the same session for all calls
- expose `close()`
- do **not** create session inside `classify()`
- do **not** create multiple `OrtEnvironment` instances

## Node name constraints
Do **not** use “first input” / “first output” selection as final production behavior.

Initialization must:
- inspect actual session input/output names
- compare them against `ModelConfig.INPUT_NODE_NAME` and `ModelConfig.OUTPUT_NODE_NAME`
- fail fast with a clear exception if they do not match

Allowed during implementation:
- inspect actual model names once in order to encode verified constants into `ModelConfig`

Forbidden:
- keeping `iterator().next()` as production behavior
- silently falling back to discovered names

## Output handling constraints
After inference:
- retrieve the output by configured output name
- do not use positional selection as final production behavior
- validate rank exactly `2`
- validate shape `[1, N]` with `N > 0`
- flatten to `float[] logits`
- validate all values are finite (`!NaN`, `!Infinity`)

Forbidden:
- blindly casting without rank/shape checks
- silently accepting unexpected output forms like `[N]` or `[1,1,N]`

## Resource lifetime constraints
Long-lived per classifier instance:
- `OrtEnvironment`
- `OrtSession`

Per-call objects:
- `OnnxTensor`
- `OrtSession.Result`

Rules:
- per-call objects must be closed inside the same `classify()` call, ideally with try-with-resources
- `OrtSession` must remain open across calls
- `OrtSession` must be closed only in `OnnxClassifier.close()`
- do not close the shared `OrtEnvironment`
- `close()` must be idempotent

# Pass-by-pass execution plan

## Pass 1 — core value/config/parser/loader classes

Implement or complete only the pure Java/runtime-support classes:

### `ClassificationResult`
Small immutable value object containing:
- predicted label
- predicted index
- confidence (preferred)
- keep API minimal

### `ModelConfig`
Central constants for Phase 5A:
- model asset path: `mobilenetv2.onnx`
- labels asset path: `imagenet_classes.txt`
- input shape `[1, 3, 224, 224]`
- input element count `150528`
- expected input node name
- expected output node name

Use `long[]` for ONNX tensor shape constants, not `int[]`.

### `LabelLoader`
- loads one label per line from assets
- trims safely
- rejects empty / invalid file clearly
- returns immutable list

### `LogitsParser`
Contract like:
- `ClassificationResult parse(float[] logits, List<String> labels)`

Responsibilities:
- reject null / empty logits
- reject non-finite values
- argmax
- map index to label
- fail clearly if index outside label range
- confidence optional but preferred
- if confidence is implemented, use numerically stable softmax with `logit - maxLogit`

No ONNX Runtime calls in these classes.

Do not broaden to UI.

## Pass 3 — implement `classify()`

Now implement `classify(float[] inputData)`.

Requirements:
- reject null input
- reject wrong length with message mentioning expected `150528`
- reject use after close
- create tensor directly from NCHW `float[]` using:
  - `OnnxTensor.createTensor(env, inputData, ModelConfig.INPUT_SHAPE)`
- run the session
- retrieve configured output by output node name
- validate output rank/shape
- flatten batch item 0 to `float[] logits`
- validate output finite
- pass logits to `LogitsParser`
- return `ClassificationResult`

Use try-with-resources or equivalent for per-call native resources.

Do not add async code.
Do not involve activity classes.

### Instrumentation tests (`src/androidTest/...`)

Do not depend on camera, gallery, UI, or bitmap pipeline in this step.

Do not implement the full bitmap → preprocess → inference instrumentation test here unless it already exists and only needs trivial wiring.
