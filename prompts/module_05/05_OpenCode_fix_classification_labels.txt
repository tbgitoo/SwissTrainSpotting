## Goal
Fix `LabelLoader` so it correctly loads labels line-by-line from the asset without introducing an extra synthetic entry.

## Root-cause guidance
The current implementation manually reads UTF-8 bytes in chunks and tries to reconstruct lines using `StringBuilder`.
This logic is error-prone across chunk boundaries and likely introduces an extra final label.

Preferred fix:
- replace manual chunk parsing with a standard buffered text reader
- use `BufferedReader` + `InputStreamReader(StandardCharsets.UTF_8)`
- read one logical line at a time with `readLine()`
- trim each line
- ignore empty lines
- keep the rest of the API unchanged

## Required behavior
After the fix:
- loading `imagenet_classes.txt` yields exactly 1000 labels
- no returned label is empty
- no synthetic extra label is introduced
- public API remains unchanged
