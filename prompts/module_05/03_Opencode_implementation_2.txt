# Scope constraints (strict)

## Implement exactly these responsibilities

### 1. `ClassificationResult`
Create a small immutable Java value object representing:
- predicted label
- predicted index
- confidence (if present; acceptable as `float`)
- optionally raw top logit if useful internally, but keep API minimal

No Android UI logic in this class.

### 2. `ModelConfig`
Create a central config/constants class for Phase 5A with:
- model asset path: `mobilenetv2.onnx`
- labels asset path: `imagenet_classes.txt`
- expected input shape: `[1, 3, 224, 224]`
- expected input length: `150528`
- expected model input name
- expected model output name

**Important:**
- inspect the model/session metadata and validate names at initialization
- if names differ from config, fail fast with a clear exception
- do not silently accept mismatches

If expected names are not yet known in code, discover them from the model once and encode them explicitly in `ModelConfig` after verification. Do not leave “first input” / “first output” magic in production code.

### 3. `LabelLoader`
Create a dedicated loader for labels from assets:
- loads one label per line from `imagenet_classes.txt`
- trims line endings safely
- rejects empty/invalid label file with a clear exception
- returns an immutable list

No model/session logic here.

### 4. `LogitsParser`
Create a dedicated parser class with a contract like:
- `ClassificationResult parse(float[] logits, List<String> labels)`

Responsibilities:
- validate logits array is non-null and non-empty
- validate all logits are finite (`!NaN`, `!Infinity`)
- compute argmax
- map predicted index to label
- optionally compute confidence via stable softmax:
  - subtract max logit before exponentiation
- fail clearly if predicted index is outside label range

Do not put ONNX Runtime calls here.

### 5. `OnnxClassifier`
Create the actual runtime class.

Responsibilities:
- obtain `OrtEnvironment` only via `OrtEnvironment.getEnvironment()`
- create `OrtSession` once in constructor / initialization path
- reuse the same session for all `classify()` calls
- expose `close()`
- run inference from already prepared NCHW `float[]`
- create input tensor using:
  - `OnnxTensor.createTensor(env, inputData, shape)`
- validate output tensor shape before parsing
- flatten output to `float[] logits`
- call `LogitsParser`

Strict requirements:
- input contract is exactly:
  - `float[]`
  - length `150528`
  - shape `[1,3,224,224]`
  - layout `NCHW`
- do **not** transpose
- do **not** repack
- do **not** reinterpret as HWC
- do **not** create session inside `classify()`
- do **not** create multiple `OrtEnvironment` instances
- do **not** couple classifier to bitmap preprocessing
- do **not** couple classifier to activity classes

Prefer a synchronous classifier API for now, e.g.:
- `ClassificationResult classify(float[] inputData)`

Threading belongs to the Activity layer in a later prompt.

## Input tensor handling (hard rule)

`OnnxClassifier.classify(float[] inputData)` must treat `inputData` as already-final model input.

Therefore:
- do not allocate a reordered copy
- do not normalize again
- do not transpose
- do not reshape logically into HWC/NHWC form
- do not inspect pixels or call any bitmap APIs
- do not perform channel swapping

The only allowed operations on `inputData` before tensor creation are:
- null check
- length check
- optional finite-value validation if added

Then create the tensor directly from that same logical NCHW data.

# Implementation details to enforce

## Input validation
Before inference:
- reject `null` input
- reject wrong length
- exception message must mention expected `150528`

## Session initialization
At initialization:
- open model from assets
- create session once
- inspect and validate input names / output names
- optionally inspect tensor info to verify expected rank compatibility


## Node name handling (hard rule)

Do not use “first input” or “first output” selection as production behavior.

Initialization must:
- inspect actual model input/output names from the session
- compare them against `ModelConfig.INPUT_NODE_NAME` and `ModelConfig.OUTPUT_NODE_NAME`
- fail fast with a clear exception if they do not match

Allowed only during implementation:
- you may inspect actual names once in order to encode the verified constants into `ModelConfig`

Forbidden:
- `iterator().next()` as final production behavior
- silent fallback to discovered names
- “if configured name missing, use first available node”

## Output validation

After `session.run(...)`:

- retrieve the output by `ModelConfig.OUTPUT_NODE_NAME`
- do not use positional output selection as production behavior
- verify the output value is a tensor-compatible object of the expected numeric type
- inspect the output tensor shape before parsing
- require rank exactly 2
- require first dimension exactly 1
- require second dimension > 0

Only after these checks:
- extract logits for batch item 0
- flatten to a plain `float[]`

Forbidden:
- blindly casting without shape checks
- assuming output structure without validation
- silently accommodating unexpected ranks such as `[N]`, `[1,1,N]`, or other variants

## Parsing
Prediction rule:
- class = argmax(logits)
- confidence optional but preferred
- if confidence is implemented, use numerically stable softmax (`logit - maxLogit`)

## Resource handling
- close tensors/results properly
- expose `close()` on classifier
- avoid leaks
- document clearly whether `OnnxClassifier` is reusable and must be closed


## Resource lifetime rules

Lifetime split must be:

Long-lived per classifier instance:
- `OrtEnvironment` (obtained via `OrtEnvironment.getEnvironment()`)
- `OrtSession` (created once during initialization)

Per inference call:
- input `OnnxTensor`
- `OrtSession.Result`

Rules:
- per-call objects must be closed in the same `classify()` invocation, preferably with try-with-resources
- `OrtSession` must remain open across calls and be closed only in `OnnxClassifier.close()`
- do not close the shared `OrtEnvironment`
- `OnnxClassifier.close()` must be idempotent

Forbidden:
- closing the session after each inference
- leaking `OrtSession.Result`
- leaking `OnnxTensor`
- creating a new session per call
