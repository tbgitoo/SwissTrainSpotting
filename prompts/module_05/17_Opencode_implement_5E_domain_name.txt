Goal:
Make conditional/out-of-scope UI messaging domain-aware based on the active specialized classifier profile, so that the current generic hard-coded train phrasing disappears. Example target behavior:
- Hymenoptera profile: "Not Hymenoptera; if classified within Hymenoptera: ants (99.0%)"
- SwissTrains profile: "Not a train; if classified within SwissTrains: Re420 (99.0%)" or equivalent specialized label

Important architectural rule:
- Do NOT put this domain display name into the Python-generated model metadata JSON.
- Treat this as app-side profile configuration, separate from ONNX export metadata.
- Keep allowed-label assets exactly as they are conceptually: pair-specific relations between MobileNetV2 and the specialized classifier.
- Keep model/profile prefixes exactly aligned with existing conventions: `hymenoptera` and `swiss_trains`.

Required new assets:
Create exactly these two files in app/src/main/assets/ :

Each file must minimally define the specialized profile identity and domain-aware fallback messaging data. Keep the schema minimal and explicit. At minimum it must support:
