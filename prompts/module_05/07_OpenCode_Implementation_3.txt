## Hard constraints

### 1. Reuse existing runtime layer
Use the existing:
- `OnnxClassifier`
- `ClassificationResult`
- `LogitsParser`
- `LabelLoader`
- `ModelConfig`

Do not reopen or redesign runtime internals unless strictly required for compilation.

Do not:
- recreate ONNX session lifecycle in UI code
- duplicate inference logic in the Activity
- instantiate ONNX runtime objects ad hoc in multiple places

### 2. Respect Module 3 contract
Input to inference must still be exactly the existing Module 3 output:

- `float[]`
- length `150528`
- shape `[1,3,224,224]`
- layout `NCHW`

Hard rules:
- do **not** transpose
- do **not** repack
- do **not** reinterpret as HWC/NHWC
- do **not** add second preprocessing logic in the Activity

The Activity must call the existing `ImagePreprocessor.preprocess(...)` and pass the resulting tensor unchanged to `OnnxClassifier.classify(...)`.

### 3. Threading / UI safety
Inference must **not** run on the main thread.

Required behavior:
- launch preprocessing + inference on a background thread
- update UI on the main thread only
- if the Activity is destroyed, finishing, or otherwise invalid before the result returns, discard the result instead of updating the UI
- do not leak Activity references through long-lived background work

Use the simplest existing Java/Android mechanism already consistent with the repo.
Do not introduce major new concurrency abstractions unless already used.

### 4. UI ownership rule
For Phase 5A Step 3, preprocessing + inference UI wiring belongs **exclusively** to the existing second screen, `ImageClassificationActivity`.

Required:
- `ImageClassificationActivity` owns preprocessing + inference triggering for the selected/captured upright `Bitmap`
- result display is updated in `ImageClassificationActivity`

Do not:
- move inference wiring into `MainActivity`
- split inference ownership across multiple Activities
- introduce a second parallel classification screen

### 5. Minimal UI integration
Display only a minimal result sufficient for Phase 5A:

- predicted label
- confidence (if already available)
- optional simple loading state
- simple error display if inference fails

Do not redesign the UI.

If a result TextView / image preview / classification screen already exists, reuse it.
Only add the smallest required UI elements if the current screen has no place to display the result.

### 6. Activity lifecycle
If `OnnxClassifier` is Activity-owned in the current design:
- initialize it once per Activity lifecycle as appropriate
- close it at the appropriate lifecycle point
- do not create a new classifier per button click if a reusable instance is already appropriate

Keep this aligned with the existing app structure and the Step 2 runtime design.

Do not create multiple long-lived classifier instances unnecessarily.
