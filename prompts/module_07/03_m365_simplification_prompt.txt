## Purpose

Module 7 is the **finalization module** of the project. It does not add product features. It prepares the codebase and Android app for **reuse, handoff, and manual distribution**.

Three concerns, one module:

| Phase | Concern | Outcome |
|-------|---------|---------|
| **7A** | Documentation | Concise JavaDoc (Android) and docstrings (Python) on public surfaces |
| **7B** | Structural review | Proposal-level package/folder review; manual cleanup guided by checklist |
| **7C** | Packaging readiness | Pre-flight review + manual APK/install checklist (Android Studio–driven) |

Module 7 also confirms **proportionate end-to-end sanity** on a physical device or emulator using the existing test suites and a short manual smoke pass — not a new CI pipeline or expanded test framework.

## Architectural placement

Module 7 sits **above** feature modules at repository root. It touches both subtrees but does not merge them.

```
SwissTrainSpotting/                    ← Module 7 scope (project-wide)
├── plans/
│   ├── 01_architecture.md
│   └── module_07/                     ← this plan + checklists
├── model/                             ← 7A Python docs; 7B folder review
│   ├── scripts/
│   ├── data/
│   └── export/
└── SwissTrainSpottingApp/             ← 7A JavaDoc; 7B package review; 7C APK readiness
    └── app/src/main/
        ├── java/.../                  ← flat package today
        ├── assets/
        └── res/
```

**Separation of execution environments:**
- **Android refactor / APK:** Android Studio (manual)
- **Python docs / folder cleanup:** editor or IDE (manual moves with import updates)
- **Agents / scripts:** may **author** docs and checklists; must **not** claim to have completed IDE-driven restructure or APK generation

## Step-by-step workflow

### Phase 7A — Documentation

**Goal:** Make public APIs and script entry points understandable for future reuse. **No behavior changes.**

#### Android (JavaDoc)

Document **public or integration-facing** types in `com.tb.swisstrainspotting`. Prioritize types a maintainer reads first:

| Priority | Types | Focus |
|----------|-------|-------|
| High | `ImageClassificationActivity`, `MainActivity` | Lifecycle, threading, acquisition modes, profile loading seam |
| High | `OnnxClassifier`, `ImagePreprocessor`, `ModelProfile`, `ClassificationRouter` | Tensor contract, session lifecycle, routing semantics |
| Medium | `LabelLoader`, `LogitsParser`, `AllowedSetLoader`, `ProfileConfig`, `RoutedResultFormatter` | Asset conventions, parsing, UI formatting |
| Medium | `ModelConfig`, `ClassificationResult`, `RoutedClassificationResult`, `RoutingMode` | Constants and result shapes |
| Lower | OCR types (`OcrAnalyzer`, `MlKitOcrAnalyzer`, `OcrResult`, `OcrTextNormalizer`) | Optional path; non-blocking contract |
| Lower | `AcquisitionMode` | Enum used by activity intents |

**JavaDoc rules:**
- Class-level: responsibility, threading constraints, asset dependencies where non-obvious
- Public methods: parameters, return value, `@throws` for checked exceptions
- Do **not** JavaDoc every private helper or regenerate obvious getters
- Do **not** change method signatures, logic, or string resources
- Match existing comment style where present (see `ModelProfile`, `ClassificationRouter`)

#### Python (docstrings)

Document **module-level** purpose and **public functions/classes** in `model/scripts/`:

| Script | Document |
|--------|----------|
| `profiles.py` | `ProfileConfig`, `get_profile`, registry semantics |
| `preprocess.py` | Canonical transform; alignment with Android |
| `discover_dataset.py`, `make_split.py` | CLI purpose, exit codes, manifest behavior |
| `train.py`, `export_onnx.py`, `verify_onnx.py` | Pipeline stage role, key outputs under `export/` |

**Python doc rules:**
- Module docstring at top of each script (one short paragraph)
- Function docstrings for non-trivial helpers; include args/returns where useful
- Reference `--profile` and paths via `profiles.py` — do not duplicate path hardcoding in prose
- Do **not** add type stubs, Sphinx site, or new dependencies
- `model/README.md` may receive **small cross-links** only if a docstring points to a workflow already documented there (optional, minimal)

#### 7A completion signal
- Public Android types listed above have class-level JavaDoc; key public methods documented
- Each Python script in `model/scripts/` has a module docstring and docstrings on main entry helpers
- `./gradlew test` and `model/` verification commands still pass (no functional diff)

### Phase 7B — Structural review

**Goal:** Review whether current organization is maintainable; **propose** improvements; guide **manual** cleanup. Restructuring is **not** agent-delivered.

#### Current baseline (for review)

**Android:** single flat package `com.tb.swisstrainspotting` (~20 Java files) — UI, ML, OCR, and routing coexist without subpackages.

**Python:** `model/scripts/` (flat), `model/data/` (profile-specific raw trees + splits), `model/export/` (artifacts), `model/plans/`.

**Root:** `plans/`, optional guides (`README_4B_training_swiss_trains.md`), `prompts/` (out of Module 7 scope unless clutter affects navigation).

#### Review tasks (proposal only)

1. **Inventory** — list Java files by concern (ui / ml / ocr / util); list Python scripts by pipeline stage.
2. **Assess** — note coupling (e.g. `ImageClassificationActivity` owns inference + OCR + routing wiring).
3. **Propose** — optional subpackage sketch for Android (example: `ui`, `ml`, `ocr`) **only if** it reduces confusion without violating AGENTS.md simplicity rules.
4. **Risk note** — flat package may be acceptable for project size; subpackages add import churn and test path updates.
5. **Decide** — recommend **keep as-is** or **manual refactor** with ordered steps.

#### Deliverable: `plans/module_07/structural_review_checklist.md`

Generate a short Markdown checklist containing:

- [ ] Current structure summary (Android package + `model/` tree)
- [ ] Findings (duplication, naming, misplaced files, doc gaps)
- [ ] **Proposal** section (recommended package/folder targets or explicit “no change”)
- [ ] **Manual steps** (if refactor chosen): Android Studio Refactor → Move; update imports; run tests; update plan references
- [ ] **Explicit deferrals** (what not to reorganize: assets layout, Gradle structure, `plans/` history)
- [ ] Sign-off line: “Structural changes applied manually: yes / no / partial”

**Important:** Checking off “proposal reviewed” does **not** mean restructuring was done. Only manual steps checked after IDE work count as applied.

### Phase 7C — Packaging readiness

**Goal:** Confirm the Android app is ready for **manual** debug (or release) APK generation and sideload installation in Android Studio. Deliver a checklist, not a build script.

#### Pre-flight review (read-only)

Verify before packaging:

| Area | Check |
|------|-------|
| **Active profile** | `ImageClassificationActivity` loads intended specialized profile (`swiss_trains` for deployment); required ONNX + JSON assets present in `app/src/main/assets/` |
| **Generic baseline** | `mobilenetv2.onnx`, `imagenet_classes.txt` present |
| **Routing assets** | `<profile>_allowed_mobilenetv2_labels.txt`, `<profile>_profile_config.json` match active profile |
| **Manifest** | Activities declared; `CAMERA` permission present; `FileProvider` configured if camera used |
| **Strings / UI** | No hardcoded user-visible text (per AGENTS.md) |
| **Assets size** | Large ONNX files acceptable for sideload; note total APK size qualitatively |
| **Secrets** | No API keys or credentials in repo |
| **Tests** | `./gradlew test connectedAndroidTest` (or project-standard subset) pass on maintainer machine |
| **Manual smoke** | Gallery + camera path; classification result; optional OCR section behavior |

**Out of scope:** keystore creation automation, Play App Signing, version-code policy, Gradle `assembleRelease` documentation as mandatory path.

#### Deliverable: `plans/module_07/apk_packaging_checklist.md`

Generate a concise Markdown checklist for a maintainer using **Android Studio**:

- [ ] Open `SwissTrainSpottingApp/` in Android Studio; sync Gradle successfully
- [ ] Confirm active specialized profile and assets (see pre-flight table)
- [ ] Run unit tests from IDE or `./gradlew test`
- [ ] Run on emulator or physical device; execute manual smoke scenarios (capture/select → classify → optional OCR)
- [ ] **Build → Build Bundle(s) / APK(s) → Build APK(s)** (or equivalent IDE menu for current AS version)
- [ ] Locate generated APK under `app/build/outputs/apk/` (path may vary by variant)
- [ ] Install on target device (USB debugging, or “Apply Changes” / Run for direct install)
- [ ] Post-install smoke: launch, classify one known-good image, confirm no crash on back navigation
- [ ] Record build variant (`debug` expected for local sideload), date, and active profile in checklist notes

Optional notes section (not required steps): release signing, minification, and Play Store are **future manual concerns**, not Module 7 deliverables.

#### Python side (reuse only)

- Confirm `model/README.md` documents `.venv`, `--profile`, and artifact copy paths
- No packaging step; checklist may include one line: “Python pipeline documented for local reuse — not distributed as binary”

## Testing / validation

Module 7 does **not** introduce a new test module. Validation combines existing automation and short manual checks.

### Automated (existing)

| Scope | Command / location |
|-------|-------------------|
| Android unit | `cd SwissTrainSpottingApp && ./gradlew test` |
| Android instrumented | `./gradlew connectedAndroidTest` (device/emulator required) |
| Python pipeline | `model/.venv` + `verify_onnx.py --profile <name>` when touching docs near export contract |

Run after 7A doc-only edits to ensure no accidental logic changes. Re-run after any manual 7B refactor.

### Manual smoke (7C)

Minimum on one device or emulator:

1. Launch app from launcher
2. Open classification via gallery and (if available) camera
3. Confirm generic + specialized result presentation (direct vs conditional routing)
4. Confirm app survives rotate/back without leak-visible crash
5. If Module 6 enabled: OCR section hidden when empty, visible when text found

Record pass/fail in `apk_packaging_checklist.md` notes.
