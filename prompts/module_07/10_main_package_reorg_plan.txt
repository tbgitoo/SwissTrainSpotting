Task: generate a Markdown package placement plan for the main Android source classes, without modifying any code.

Context
- Project: SwissTrainSpotting Android app
- Current issue: many or most main source classes are still flat under the root Java package:
  com.tb.swisstrainspotting
- I want a semantic package cleanup plan, not a module/phase-based structure.
- The module structure used for tests/reporting must NOT drive the main package structure.
- I want Cursor to determine / confirm the best semantic package placement for each class.

Architectural intent
- Keep package structure minimal, semantically meaningful, and reusable.
- Target package families are along these lines:
  - com.tb.swisstrainspotting.ui
  - com.tb.swisstrainspotting.ocr
  - com.tb.swisstrainspotting.onnx
  - com.tb.swisstrainspotting.imageprocess
- Additional packages are allowed only if clearly justified by actual class responsibilities, and should remain minimal (for example config, model, or util if truly needed).
- Activities should remain in a central application-oriented package (typically ui), because they are the app-specific orchestration layer and not intended to be reusable components.

Hard constraints
- DO NOT move files.
- DO NOT edit code.
- DO NOT rename classes.
- DO NOT refactor architecture.
- DO NOT invent new abstractions or layers unless there is a very strong reason.
- DO NOT organize main code by moduleXX or phaseY.
- Keep the package taxonomy small and pragmatic: not much more, not much less.

What to inspect
- Inspect the main Android source tree (not androidTest) and enumerate all classes currently under:
  app/src/main/java/com/tb/swisstrainspotting
  including subpackages if they already exist.
- Determine the best semantic package placement for each class based on its actual responsibility and coupling.

Required output
Create a Markdown file at:

plans/module_07/main_package_reorg_plan.md

## 1. Proposed target package structure
