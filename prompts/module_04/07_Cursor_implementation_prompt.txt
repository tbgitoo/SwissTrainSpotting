## Hard constraints

### 1. Shared pipeline, two profiles
The implementation must support:

- `--profile hymenoptera`
- `--profile swiss_trains`

All scripts must resolve paths through a shared `scripts/profiles.py`.

Do not hardcode dataset roots or artifact names in individual scripts.

### 2. Only Phase 4A is executed now
You must implement support for both profiles, but in this task you only:
- run commands for `hymenoptera`
- validate `hymenoptera`
- generate `hymenoptera_*` artifacts

`./data/raw_swiss_trains/` may remain empty and this must **not** be treated as a blocker for this task.

### 3. Local Python environment is mandatory
All Module 4 commands must run from a **project-local virtual environment** under:

- `./.venv`

Requirements:
- create `.venv` if missing
- activate `.venv`
- install dependencies from the already existing `requirements.txt`
- set `TORCH_HOME="$HOME/.cache/torch"` before pipeline execution

Do not assume a working global Python environment.

### 4. Preserve the Python ↔ Android preprocessing contract
This is a hard constraint.

The canonical preprocessing must remain:

- resize to `(224, 224)` by stretch
- RGB
- divide by 255
- ImageNet mean/std normalization
- NCHW
- float32

Do **not** use:
- `RandomResizedCrop`
- `CenterCrop`
- letterboxing
- OpenCV BGR
- separate train/verify preprocess implementations

Use one shared `scripts/preprocess.py`.

### 5. Transfer-learning strategy is fixed for baseline
Implement the required baseline exactly as planned:

- pretrained `mobilenet_v2(weights=MobileNet_V2_Weights.IMAGENET1K_V1)`
- replace final classifier head only
- freeze all backbone parameters
- train head only
- Adam, lr `1e-3`
- batch size `16` (fallback `8` if needed)
- `CrossEntropyLoss`
- target epochs: `15`

Do not introduce a broader fine-tuning strategy in this task.
Optional unfreezing remains out of scope for implementation now.

### 6. ONNX export contract is fixed
Export must produce:

- input name: `"input"`
- output name: `"output"`
- input shape: `[1, 3, 224, 224]`
- logits output only
- opset 17
- no dynamic axes

Do not export softmax into the ONNX graph.

### 7. Deterministic class ordering and split
Class identity comes from folder names.
Class order must be lexicographic.
Validation split must be deterministic and manifest-based.
Raw files must never be moved or rewritten.

### 8. README and dataset handling
Do not automate public dataset download inside pipeline code.
Document dataset preparation commands in `./README.md` only.

The dataset has already been prepared locally under:
- `./data/raw_hymenoptera/`

The script pipeline should assume the data exists and validate it.

## Required implementation details

### A. `profiles.py`
Implement a small profile registry as the single source of truth for:

- raw root
- split manifest path
- artifact prefix
- minimum class/image counts

Support both profiles:
- `hymenoptera`
- `swiss_trains`

Even though only `hymenoptera` will be executed now.

### B. `preprocess.py`
Implement the canonical shared preprocessing used by:
- training
- validation
- export verification
- optional fixture generation

Requirements:
- PIL load via `Image.open(...).convert("RGB")`
- resize `(224, 224)` only
- tensor conversion
- ImageNet normalization
- helper to produce `(1, 3, 224, 224)` tensor if useful for verification/export

Do not duplicate preprocessing elsewhere.

### C. `discover_dataset.py`
Implement:
- profile selection via `--profile`
- class discovery from immediate subfolders
- lexicographic class ordering
- image counting
- profile-specific minimum count enforcement
- clear stdout summary:
  - class IDs in order
  - counts per class
  - train/val estimate if helpful

Fail clearly if:
- profile unknown
- raw root missing
- too few classes
- too few images in any class

### D. `make_split.py`
Implement:
- deterministic manifest generation per profile
- 20% validation split, minimum 1 image per class
- lexicographic filename ordering
- no file mutation
- creation of `./data/splits/` if missing

The manifest must include:
- version
- profile
- seed
- val_ratio
- entries with `class_id` and image path

Re-running with unchanged data must produce identical output.

### E. `train.py`
Implement:
- profile-aware training
- loading train vs val from raw tree + manifest
- MobileNetV2 head-only transfer learning
- checkpoint saving to `./export/checkpoints/{prefix}_best_model.pt`

Checkpoint must include at least:
- `profile`
- `state_dict`
- `class_to_idx`
- hyperparameter snapshot

Use the simplest correct implementation.
Do not introduce notebooks or training frameworks.

### F. `export_onnx.py`
Implement:
- profile-aware checkpoint loading
- model rebuild + head reconstruction
- ONNX export with fixed `input` / `output`
- generation of:
  - `{prefix}.onnx`
  - `{prefix}_labels.json`
  - `{prefix}_model_metadata.json`

These artifacts must derive label ordering from the checkpoint, not by accidental re-discovery only.

### G. `verify_onnx.py`
Implement:
- profile-aware ONNX verification
- ONNX checker
- onnxruntime inference
- metadata consistency checks
- one real-image inference from the selected profile raw tree
- finite logits
- shape `[1, N]`
- `N == len(labels)`
- print top-1 class + confidence (softmax in script only)
- optionally emit `{prefix}_test_fixture_tensor_head.json`

Exit non-zero on failure.
